    What this option is

    home-search-field is drawn quiet and inert on home itself — placeholder text only, no cursor, pointer-events: none on the text — because the whole field is one tap target that hands off to ask (model b). record-button is full-width, 56pt tall and the single filled shape at rest: Von Restorff plus sheer size makes it the obvious next action even with the field sitting right above it, and Fitts's law favours it further — it is the larger target, not just the differently-coloured one.

    Handoff (R9)

    Tapping the field pushes ask with the keyboard already up; nothing is retyped. The field's placeholder ("Ask Andy", C2) is also its accessibility label (C3) — there is only one thing this control does, so one name is enough. Opening ask any other way (e.g. from a briefing-card person link) never auto-submits, matching R9.

    VoiceOver on home: "Ask Andy, button." On arrival in Ask: focus moves straight to the text field, keyboard already up.

    Where this option costs something

    Model (b) reopens the exact trade the brief's §4 describes: a person who wants to filter by name has to leave home to do it, even though that part is free and instant underneath. It is "the field that only acts after you leave," which day 5 rejected before free name search existed — the rejection's reason has changed, but the shape is the same one day 5 turned down. [call] #3 (return-key behaviour) doesn't apply here: once inside ask, the field's return key follows whatever ask already decided for ask-submit-button, not a new decision.

    #4 — the back bubble

    Same finding as Option A (shared chrome, not an option-specific difference): not removable from the system back button in RNS 4.26.2. Toggle "pushed screen" above to see it. Recommendation: accept it.

    Accessibility

    • record-button and the field are each well over 44pt tall (56pt / 40pt) — no target is close to the floor.
    • At the largest accessibility size the field and button both grow rather than clip; because they're already stacked, nothing needs to reflow into a new row the way Option A's single bar does.
    • home-index has the least headroom of the three options — this stacked bar is the tallest bottom chrome (field + button vs. one row), so it is the first one to re-measure against 27 letters at the largest type size on a real device (R7).
    • Placeholder text ("Ask Andy") on paper uses colors.placeholder, 5.0:1 — reused, not new.
