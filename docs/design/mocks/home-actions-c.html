    What this option is

    home-search-field (model a) runs the full width of the bottom edge, like iOS Contacts (brief §5). record-fab (new) floats bottom-right, overlapping the list rather than sharing a row — closer to Voice Memos' "capture is its own big thing" feel, but kept to a pill with the word "Record" rather than a bare icon circle, because R1 forbids an icon-only Record control. That is a deliberate break from the usual Material/iOS FAB convention (icon-only) — Jakob's law cuts against this option for that reason, flagged below.

    Typing / offline / keyboard

    Same mechanics as Option A — filters in place, offline keeps working, home-ask-row under the results. The difference is only in where record-fab sits: while the keyboard is up it rises to stay clear of it rather than being covered, but it never fully leaves the way Option A's bar-mounted Record does — so it keeps floating over the last visible rows of the filtered list, which is the risk below.

    VoiceOver order: nav bar → list content → home-search-field → home-ask-row → record-fab. Toggle "Up" to see it rise above the keyboard.

    Risk: the float can cover a row (R1)

    R1 says Record must never be covered by the list — it says nothing about Record covering the list, but a control sitting on top of scrolling content is the same problem in reverse: at rest it already overlaps where the 20th row would sit if the list were one row longer, and at the largest Dynamic Type size (toggle above) the fab grows and the risk grows with it. This is the one option where "never covered / never covering" has to be checked both ways on a real device, across list lengths — Option A and B's anchored bars don't have this failure mode at all.

    #4 — the back bubble

    Same finding as Options A and B (shared chrome): not removable from the system back button in RNS 4.26.2. Toggle "pushed screen" above. Recommendation: accept it.

    Accessibility

    • record-fab is 52pt tall at rest (60pt at the largest type size) — clears the 44pt floor, but is the only one of the three options whose Record target sits over live content rather than a dedicated bar, which is a bigger target-confusion risk for VoiceOver swipe order and for Switch Control's scan order (not simulated precisely here).
    • home-index has the same bottom clearance as Option A (same single-row field height); the fab floats above both the field and the index's lowest letters, so it must be checked that it never sits over the index either, not just the list.
    • The field's edge, placeholder and clear/cancel controls reuse the same tokens and sizes as Option A — no new pairing introduced.
