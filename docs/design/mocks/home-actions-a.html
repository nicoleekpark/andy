    #4 — the back bubble

    Toggle "pushed screen" above. nav-bar-back already lost its text label in copy-build-4 (chevron alone). The glass circle behind that chevron is a separate, newer iOS 26 default and — checked against node_modules/react-native-screens 4.26.2's own types — not removable: hidesSharedBackground is typed to "right"/"left" subviews only, never the back item, which matches the Apple forum report the brief cites. A custom left item could in principle drop the glass, but iOS 26 gives every bar item its own glass by default regardless — and it would forfeit the native long-press back menu R13 requires, which is generated from the system back item and cannot be reattached to a custom one without hand-building it. Recommendation: accept the bubble (option iii) — the only way around it is a fully custom-drawn header, a separate, larger decision this brief doesn't need to make.

    Accessibility

    • home-search-field's only edge is colors.edge on paper, 3.2:1 (WCAG 1.4.11) — reused, not new.
    • record-button, cancel-search-button, clear-search-button are each 44×44pt minimum; the field itself is 44pt tall.
    • Toggle "largest accessibility size": the bar wraps to two rows rather than truncating "Record" — R7's "labels wrap and never truncate" rule.
    • home-index ends above the bar with room to spare at normal type; at the largest size the bar grows ~24pt taller, which is the measurement to re-check on device with the real home-index component (not simulated precisely here) against 27 letters (R7).
    • Reduce Motion: entering/leaving search mode crossfades the bar's contents rather than sliding, per STYLE's reduced-motion rule.
