What this mock answers

Model and screen compose independently: pick a model with the top rig, then step through the same set of states underneath it. Any state that doesn't apply to the current model is disabled in the screen rig, with a one-line reason above the phone.

M1 — Chooser over a scrim

Record's label becomes "New note" (it can no longer say "Record" once it opens a menu — one action, one name). Tapping it dims home and opens capture-menu with three equal-weight rows. Tapping the Record row closes the menu and starts listening immediately — the only way voice stays at two taps rather than three.

VoiceOver on open: focus moves straight to the Record row (not Close) — "Record. Opens voice recording." · Write: "Write. Opens a blank note." · Photo: "Photo. A card, a page of notes, a screenshot. Opens photo options." · Close reachable by swipe or the two-finger-Z escape.

M2 — Voice first, doors beside

Record is untouched — same word, same shape, same position — and starts listening on one tap. A small, quiet, separately-labelled capture-more-button ("Write or add a photo") sits beside it and opens the same menu shape, holding only Write and Photo. Because Record keeps its single job, nobody who only means to write ever risks meeting the microphone first.

VoiceOver on open: focus moves to Write (the first row in this two-row menu), then Photo, then Close by escape. capture-more-button itself: "Write or add a photo, button."

M3 — Voice first, doors after

Record is untouched on home. On a first-ever tap (try "mic permission: not yet asked"), it opens record--ready with Write-it-instead and Photo-instead already visible, and only asks for the microphone — never auto-starting before that's answered. Once granted, every later tap goes straight to record--listening. Tapping either secondary link while listening stops and discards the just-started, empty recording first (try "listening" with this model, then tap "Write it instead").

Named cost, not hidden: after the first grant, a returning user who only wants to write still taps Record first — a live microphone briefly engages before they notice and tap away. Toggle "mic permission: granted" + screen "listening" to feel this for yourself.

Shared across all three (not a model difference)

  • Photo, one item, two steps. Every model's Photo door opens the same photo-source-dialog — Take a photo / Choose a photo — reusing today's scan-card-button mechanism.
  • Every photo goes through its words first. A card's OCR misreads a name the way speech mishears one, so a card now lands on record--picture too, not a direct save — one law for every picture (try "record--picture (misread name)").
  • Paste is visible. The empty Write body shows a system-style ClipboardPasteButton beside the placeholder — additive to the normal long-press edit menu, not a replacement for it.
  • Photo offline says so first. Toggle "connection: offline" then tap into the Photo door (M1/M2: via the menu; M3: via "Photo instead") — a notice appears before any camera or picker, never a picker that opens and then fails.

Recommendation

M2. It is the only option that reaches one-tap voice without M3's recurring live-mic cost on Write, and the only one that leaves both home-actions.md and record-flow.md — finished hours before this brief — completely untouched. M1 is the right call if the owner weighs "every door equally visible" above the one-tap speed-up and accepts renaming "Record"; it is the owner's own first idea, built here in full rather than argued out of. M3 is not recommended: its first-use fix genuinely works, but the cost it reintroduces on every later Write is real and recurring, not an edge case — see the full write-up in capture-doors.md.

Accessibility, shared across all three

  • Targets: every menu row, the close control, the secondary links and capture-more-button are at least 44×44pt, independent of label length.
  • No icon-only commands: every menu row shows its word; the icon is decoration beside it, never the only cue.
  • Reduce Motion (toggle above): the menu crossfades only — no fan-out, no spring. The recording dot's pulse freezes.
  • Dynamic Type (toggle above): menu rows wrap, never truncate; capture-more-button (M2) drops to its own row under Record; M3's two secondary links stack vertically.
  • Contrast: no new pairings — scrim, edge, placeholder, moss/paper and the one named alert exception (the recording indicator) only.
