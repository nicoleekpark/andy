What this option is

On typing and transcript, about-field and the body sit in two sections separated by a hairline rule (colors.line) — Gestalt's law of common region: grouping the two labels and their fields visually turns "a blank box" into a legible two-part form at a glance, which is #16/#17's actual complaint. No new copy: both labels are the exact strings from §7, drawn uppercase through the same field-label style every other field on this screen already uses.

Chip suggestions

Suggestions render as small chips rather than full-width rows — more compact when there are two or three, and visually distinct from review's row-based picker so it doesn't look like a second, required step. It is still the same person-search component and the same query as #30 (brief R6) — only the outer chrome differs, which keeps "one person search, built once" true while giving this screen its own, lighter touch.

VoiceOver, chip: "Priya Kapoor, friend · 4 notes · last 2026-10-02. Picks this person."

Declared, as a chip (R7)

A picked or scoped subject becomes a filled moss chip holding the name, with Change inside it — the "one line" family from R7 (not a field you could accidentally edit), styled to match the suggestion chips above it rather than a plain sentence.

Auto-continuing bullets (R10)

No toggle. Typing "- " and pressing Return continues "- " on the next line, live in the mock's own textarea — demonstrating the brief's invited alternative without adding a visible control. The placeholder still says both a paragraph and a quick list work; this is a convenience for the list case, not a claim that formatting is stored.

Accessibility

  • Chips meet 44pt even at their shortest label by fixed vertical padding, not content-driven height.
  • The section divider is decoration (colors.line), so it carries no meaning alone — the eyebrow labels say what each half is, per brief §8's "no colour/decoration-only states".
  • VoiceOver order: About who? label → field/chip → chip count ("2 people found") → What you said/want to remember label → body, top to bottom, matching reading order.
